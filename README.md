# 项目介绍：

本项目是依据b站“网易云音乐小程序”从零到一自己搭建的一个简易音乐app。该音乐小程序是一款聚焦多元音乐娱乐需求的微信小程序，支持推荐歌曲播放、轮播图展示、推荐歌曲排行榜、微信快捷登录、音乐相关视频播放、按歌曲名/歌手/专辑搜索及AI聊天功能，依托微信生态即开即用、无需安装，为用户提供便捷的音乐娱乐体验。

项目以微信原生小程序框架为基础，不依赖复杂第三方框架，降低入门门槛，同时覆盖小程序开发的核心场景与高频需求——从基础的页面布局、样式设计、数据绑定，到进阶的网络请求封装、本地缓存运用、页面路由跳转，再到实战级的功能模块开发（如列表渲染优化、交互逻辑实现等），完整还原小程序开发的真实工作流程。

编程语言主要采用的是：JavaScript

API由本地服务器加云服务器共同提供。

项目设计遵循“循序渐进、由浅入深”的学习逻辑，每个功能模块都对应核心知识点，通过“需求分析→技术拆解→代码实现→测试优化。同时，项目采用贴近实际开发的规范（如代码模块化、函数封装、注释规范），帮助学习者养成良好的开发习惯，为后续独立开发商业级app打下坚实基础。

# 三、项目架构

模块分层：

• MVC模式（Model-Viewer-Controller）

① Model层（bean）：包含小程序的业务数据管理部分，通过微信小程序本地缓存（wx.setStorageSync/wx.getStorageSync）实现数据临时持久化；定义歌曲、歌单、用户、播放记录等数据结构，同时负责对接外部音乐/AI接口的请求参数封装、响应数据解析，作为应用的业务数据模型。

② View层（pages/components）：负责UI展示，定义推荐歌曲页、排行榜页、视频播放页、搜索页、AI聊天页等界面，以及轮播图、歌曲卡片、播放控件等UI组件；用户通过这些界面组件与小程序交互，同时将接口返回的歌曲列表、排行榜数据适配到视图中，实现内容展示。

③ Controller层（utils/logic）：通过调用外部API接口实现业务逻辑与视图的交互；在用户点击播放、搜索歌曲、发送AI聊天消息等操作时，通过控制器方法发起API请求，解析响应数据后动态更新视图（如播放状态切换、搜索结果展示、聊天消息渲染）。

面向事件的设计：

代码采用事件监听模式处理用户交互事件（包括点击播放按钮、滑动轮播图、搜索输入、视频播放/暂停等），通过这些事件触发Controller层的API请求操作，完成歌曲播放、内容搜索、聊天消息发送等功能的执行与界面状态变换。

开发架构：

• 前端开发：设计简约直观的UI界面，包含轮播图、歌曲卡片、播放控件等组件，同时适配微信小程序在不同手机屏幕尺寸下的显示效果；核心负责接口调用、数据解析、视图渲染与交互逻辑实现，保障界面的一致性与操作流畅性。

• 接口对接层：统一封装外部音乐/AI接口的请求逻辑（如请求头配置、参数拼接、异常处理），实现接口调用的复用性与可维护性，保障与外部服务的稳定通信。

• 后端开发（云函数）：实现歌曲数据拉取、用户信息同步、播放记录存储、AI聊天接口调用等核心功能，保障数据传输的稳定性与业务逻辑的可靠执行。

## 九、网络通信

### 9.1 设计目标

网络通信章节旨在规范“特马头音乐”小程序与后端服务之间的数据交互方式，确保通信过程**稳定、安全、高效**。通过统一的接口调用封装、错误处理机制与数据缓存策略，提升用户体验并降低服务器压力。

### 9.2 通信架构概览

|     |     |     |
| --- | --- | --- |
| **模块类型** | **通信方式** | **说明** |
| 小程序前端 | HTTPS 请求 | 使用 wx.request 与后端接口通信 |
| 本地服务器 | RESTful API | 提供音乐数据、用户信息、播放记录等核心业务接口 |
| 云服务器 | 云函数 / API | 提供 AI 聊天等动态数据服务 |

# 十四、软件体系结构与质量

### 一、软件体系结构（Software Architecture）

#### 1\. 结构范式

**“前端-混合服务”两层架构**（Garlan & Shaw 定义）：

**Architecture = 构件（Components） + 连接件（Connectors） + 约束（Constraints）**

|     |     |     |     |
| --- | --- | --- | --- |
| **元素** | **职责** | **本程序实现** | **备注** |
| **构件** | 可复用计算或数据单元 | ① 页面/组件（WXML+JS） ② 工具模块（request、cache） ③ 本地服务器（音乐业务） ④ 云服务器（AI 聊天） | 音乐本地，AI 在云端 |
| **连接件** | 构件间交互机制 | wx.request（HTTPS） wx.setStorage（本地缓存） 事件总线（emit/on） | 统一封装在 /utils/request.js |
| **约束** | 拓扑、接口与生命周期规则 | ① app.json 路由表 ② 本地 API 返回格式 {code,message,data} ③ 页面生命周期 onLoad→onReady→onUnload | 强制单向数据流 |

#### 2\. 拓扑示意图（文字）

1.  ┌─ 页面/组件构件（wxml+js)
2.  │ ├─ wx.request① ─→ 本地服务器（音乐/用户/播放）
3.  │ └─ wx.request② ─→ 云服务器（AI 聊天）
4.  └─ 本地缓存侧通道（wx.setStorage）

- 音乐业务与 AI 业务**分离部署**，仅连接件地址不同 → **低耦合、易扩展**。

#### 3\. 架构风格

- **MVC 微内核**：
    - Model = 本地缓存 + 服务器 JSON（本地/云）
    - View = 页面 WXML
    - Controller = Page 实例 + utils 模块
- **管道-过滤器（Pipe-Filter）**：

请求流：wx.request → 拦截器（token、签名）→ 解析器（json→model）→ 渲染管道（setData）
